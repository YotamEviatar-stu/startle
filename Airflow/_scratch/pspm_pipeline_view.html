Airflow · GLM path · design proposal

The pipeline PsPM actually specifies

Nine stages, each with a plain-language read and a plot of the real operation on real signal.
every constant traceable to pspm_resp_pp.m, pspm_init.m, or pspm_bf_r*rf_e.m. Six stages already match the code as written. Three things change — and the largest of them is not a threshold, it is an architecture.

The part that surprised me

PsPM does no artifact rejection in preprocessing at all. pspm_resp_pp.m enforces exactly one rule — ibi < 1 s drops the later cycle — and nothing else.

“No artifact/amplitude-based cycle rejection … PsPM leaves this to the downstream GLM’s own missing-epoch mechanism (model.missing), not to pspm_resp_pp.”

So the ten per-trial gates in the code today and the five per-cycle gates I proposed earlier are both outside PsPM. The PsPM-shaped answer is neither: mark bad time epochs, in seconds, and hand them to the GLM, so the exclusion lives in the design matrix rather than as a verdict stapled to a trial or a breath.

The nine stages

● unmarked = already correct in the code ● marked = changes
1
Mean-centre, filter, downsample change 2

Strip out everything that is not breathing. The slow wander of the sensor baseline goes first, then anything faster than about one breath every two seconds — what is left is a clean oscillation you can count. This copy is only ever used to find when breaths happen; nothing is measured on it.

pspm_resp_pp.m Stage 1
resp - mean(resp) once, on the raw trace butter(1) LP 0.6 Hz filtfilt \ two SEPARATE passes, butter(1) HP 0.01 Hz filtfilt / not one butter(2, band) downsample -> 10 Hz
The code designs a single 2nd-order bandpass. Same nominal order, different transition band and phase — so zero-crossings land elsewhere, which moves RP for every breath and shifts the window RA is measured over.
AB22 / evening, 27 s. Grey: raw trace, mean-centred. Teal: after both filter passes, rescaled to overlay. Slow drift is gone; the breath is not.
2
Median filter matches
pspm_resp_pp.m Stage 2
medfilt1(newresp, ceil(newsr)+1) = 11 samples at 10 Hz
3
Cycle detection — bellows rule matches

Find where each breath starts. On a cleaned trace, inspiration begins where the signal falls through zero, so counting those crossings counts breaths — no peak-picking, no amplitude threshold.

pspm_resp_pp.m Stage 3
find(diff(sign(newresp)) == -2) / newsr
Falling zero-crossings on the signal itself, not its derivative. A flow transducer is bellows-type physics, so the derivative (“cushion”) rule would be the wrong one here.
Grey: the filtered copy. Teal: after the 11-sample median filter. Ticks below: one per falling zero crossing, i.e. one per detected inspiration onset.
4
The only rejection rule PsPM has matches
pspm_resp_pp.m Stage 4
ibi = diff(respstamp); respstamp(find(ibi < 1) + 1) = []; single pass, original list
A hard 1 s floor and nothing more. There is no upper bound — the 10 s marker in the source is a plotting flag, not an exclusion.
5
RP / RA / RFR per cycle change 1 · implemented

Now measure each breath. Between one onset and the next you get three numbers: how long it took (RP), how deep it went (RA, simply the highest point minus the lowest), and how fast air moved (RFR, depth divided by duration). Crucially these are read off the original untouched trace, not the filtered copy you just counted on.

pspm_resp_pp.m Stage 5
RP = diff(respstamp) RA = range(resp(win)) on the NATIVE-rate untouched trace RFR = range(resp(win)) / ibi
The code measured on the 25 Hz cache, where a sharp inspiratory apex is already smoothed away by the resample. On a 15 ms apex the true range is 4.4919 and the 25 Hz trace gives 3.7415 — a 17% shortfall that grows with how sharp the breath is, i.e. it bites hardest on exactly the startle breaths. Now fixed by caching the native trace’s running min/max instead of the trace itself.
One breath, shaded. The bracket at the right is max minus min over that window on the raw trace — that value is RA.
6
Assign and interpolate matches

Turn one number per breath into a continuous line. Each breath's value is pinned at the moment that breath ended — you only know how deep it was once it is over — and straight lines join the dots onto an even time grid.

pspm_resp_pp.m Stage 6
interp1(respstamp(2:end), respdata, newt, 'linear')
Each value is anchored to the cycle’s closing crossing, not its start; edges use nearest-neighbour, never linear extrapolation.
Dots: one RA value per breath, each placed at the breath’s closing crossing. Line: linear interpolation between them onto the regular grid.
7
Per-modality sensitivity filter matches

Tune the line to the timescale a response lives on. A startle response unfolds over seconds, so anything slower than that is drift and anything faster is noise. The filter runs forwards only, so a sample is never shaped by the future.

pspm_init.m · defaults.glm
RP HP 0.01 Hz LP 1 Hz order 1 uni (causal) RA HP 0.001 Hz LP 1 Hz order 1 uni RFR HP 0.001 Hz LP 1 Hz order 1 uni
The easiest place for silent drift, and the code gets it right: RP is filtered less aggressively at the low end than RA and RFR. One shared high-pass across all three would collapse a distinction PsPM makes on purpose.
Grey: the interpolated RA series. Teal: the same after the causal 0.001 Hz high-pass and 1 Hz low-pass. Both z-scored so the shape change is visible.
8
Basis functions and design matches

This is the shape you are looking for. Each measure has a known response curve — a bump with a published peak time and width — and the model asks how strongly that fixed shape is present after each stimulus. The answer, one number per condition, is the score.

pspm_bf_rprf_e.m · rarf_e · rfrrf_e
support -10 s ... +30 s RP mu 4.20 sigma 1.65 no derivative RA mu 8.07 sigma 3.74 + derivative RFR mu 6.00 sigma 3.23 + derivative spm_orth -> normalise to unit range
Published constants, not hyperparameters — matching to the decimal is what keeps the method traceable to Bach et al. (2016).
The three response functions on their shared −10…+30 s support. RP peaks first at 4.2 s, RFR at 6.0 s, RA last at 8.07 s. Zero marks event onset.
9
Fit change 3

Fit once, for the whole session. Plant the response curve at every trial onset, add them up, and find the single scaling that best matches the measured line. Bad stretches are declared missing so they are simply not part of the comparison.

pspm_glm.m
one design per session, per-condition event trains convolve -> causal HP -> mean-centre -> orthogonalise centering = 1 latency = 'fixed' model.missing bad epochs IN SECONDS, into the design
The fitting machinery already matches. What changes is what feeds it: the ten per-trial gates come out, replaced by a missing-epoch list keyed on measurability — dead signal, lost detector lock, hand labels — never on response size. An 8× breath is either an artifact or the startle response, and amplitude alone cannot tell you which.
Grey: the series being regressed. Teal: the fitted model. Vertical lines: trial onsets, where the response function is planted.

Order of work

#changewhy this order
1RA/RFR at native rate
implemented, awaiting FORCE_RELOAD		 Largest effect and it changes the cache, so everything else must be measured after it.
2Rejection → missing epochs Mostly deletion, plus a short epoch list. No new thresholds to calibrate.
3Cascaded filter passes Measure both frequency responses first, then decide. Free to tune, no reload.

Re-run the endpoint once, after all three — not after each.

What this does not buy is a result. The RA endpoint currently runs opposite to the hypothesis and nothing here is a reason to expect that to flip; change 1 is the only one with a mechanism that could move it, because it corrects a bias acting specifically on large breaths, and it could move it either way. The 17% figure is from a synthetic sharp apex — the real magnitude depends on how much breath energy sits above 12.5 Hz and cannot be measured from the 25 Hz cache alone.
